# Editing and deleting your own messages

`Client::edit_message` and `delete_message` act on a message of the open room that is the user's own, sent, and text (not a system message). The server's four public settings (`Message_AllowEditing`, `Message_AllowDeleting` and their `...BlockEditInMinutes` / `...BlockDeleteInMinutes`, where 0 is no limit) are read once per sync cycle, next to the custom emoji, and become a `MessagePolicy` (`rc_core::policy`), sent as `Event::MessagePolicy` when it changes. A server that doesn't say, or a failed read, means everything allowed with no limit. The pure rules `can_edit` and `can_delete` combine the policy with the author, the delivery state and the message's age. Changing messages of others takes permissions that the client doesn't read: the server refuses and the refusal is shown.

- **Answer:** every request ends in one `Event::MessageAction` (message, `Edit` or `Delete`, and `Ok` or an `ActionError` with a text to show). A message the rules don't allow is refused at once, without a request; a blank edit is refused; an edit to the text it has succeeds without one. An edit puts the server's copy in the timeline (`Timeline::replace`) and a deletion removes the message at once; the push that follows changes nothing. An answer after a logout is dropped, and a dead token ends the session.
- **Qt side:** the `Viewer` carries the user's id and the policy, and the `MessageList` model has `canEdit` and `canDelete` roles, worked out for the current time each time they are read. `Room` has `edit`, `remove`, `lastEditable`, `messageText`, the `actionDone` signal and an `actionError` text for the room page's dismissable error bar.
- **QML:** a message that can be changed has a "..." button (clear until the pointer is over the message) and a right-click menu with Edit and Delete (and Quote, see [Quoting](quoting.md)); Delete asks for a confirmation. Edit puts the composer in edit mode (a bar, the text, "Save"); Up in an empty composer edits the newest editable message, Escape or opening another room cancels and brings the draft back. A failure keeps the composer in edit mode.
- **Spix:** popups hang off the window's overlay while open, so their items are addressed from the window (`mainWindow/msgEditAction`) and exist only then. A `Dialog` or `Menu` is not an item, so the dialog is named through its content. Pointer handlers (`TapHandler`) didn't react to Spix clicks; the right-click uses a `MouseArea`.
