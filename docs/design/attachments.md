# Attachments

A message carries its file attachments (`rc_api::Attachment`, `domain::Attachment`): title, the path of the original, description, size, and for an image the path of the picture and its dimensions in pixels. Quotes are read as such (see [Quoting](quoting.md)), other kinds of attachment (integrations) are not, and a malformed entry is skipped without failing the message. The picture of a big image is a thumbnail the server made; the original stays behind `link`.

- **Download:** the files are under `/file-upload/`, which answers 403 without the login headers, so QML can't load them. `RestSession::file` takes the server path of a message, refuses anything that doesn't start with `/file-upload/` (a full URL, another place on the server, `..`, a query), so the login headers can't go anywhere else, and decodes each segment before the request escapes it again.
- **Cache:** images go through the same bookkeeping as avatars (`downloads.rs`), with `Refresh::Never` instead of a refresh once per session. An uploaded file never changes, so when messages enter the timeline (the same places that want the authors' avatars) the actor looks each image up in the cache by `CacheKey::attachment` (server, path): a file that is there goes to the frontend at once (`Event::Images`: path and file) and is never downloaded, any other is downloaded once per session, at most four at a time, off the actor and tagged with the login attempt. A type the cache doesn't keep, or a refusal, means no image and is only logged; a download that failed for lack of a connection is wanted again when the image next comes up. Logging out sends an update that forgets every image; the files stay.
- **Qt side:** the hub keeps the files as URLs like the avatars (`ImageUrls`, `file://<path>?v=<n>`). The `MessageList` model has an `attachments` role, a list of maps (`title`, `description`, `size` in words, `link`, `isImage`, `image`, `width`, `height`), made by `attachment_view`. `link` is the server's address (the `Viewer` knows it) plus the path; `image` is the local file URL, empty until the download is done, when only the rows of messages that show that image get a `dataChanged` for the role. The delegate draws an image inline at its size (at most 360 wide), under a grey box until it loads, and a file as a link with its size. Both open `link` with `Qt.openUrlExternally`, without the token: it works when the browser has a Rocket.Chat session. Downloading through the app comes with file upload ([PLAN.md](../../PLAN.md), Phase 5).
- **Slint side:** `rows::attachment_rows` makes an `[AttachmentRow]` (the same fields as the Qt maps, `image-url` being the file URL the tests read and `image` the loaded picture) for messages that have files, and the empty model for the rest. `message_delegate.slint` draws them like the Qt delegate, with the sizes of `theme.slint`; the body is hidden when empty and there are files or quotes. Clicking opens `link` through `open-link`. There is no right-click link menu yet.
